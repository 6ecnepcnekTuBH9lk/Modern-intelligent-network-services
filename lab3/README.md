# RAG по PDF

Основной файл: [rag_experiments.ipynb](rag_experiments.ipynb). Система отвечает на вопросы по исследовательской статье о настройке языковых моделей на основе человеческой обратной связи. Исходный PDF и учебный ноутбук загружаются из локальной `lab3/sources/` или, при её отсутствии, из `_reference/`. Исходные документы не включены в Git.

```text
lab3/
  rag_experiments.ipynb  - запуск экспериментов и сохранённые выходы
  rag.py                 - PDF, разбиение, поиск, генерация, память
  questions.py           - фиксированные вопросы и отрывки с доказательствами
  experiments.py         - протоколы и таблицы семи экспериментов
  review.json            - разметка ответов и ссылок для конкретных результатов
  review_results.py      - применение разметки и пересчёт сводок
  verify_results.py      - проверка сохранённых результатов
  run_notebook.py        - запуск всех ячеек выбранным интерпретатором
  requirements.txt       - проверенные версии зависимостей
  results/               - таблицы CSV и полные трассы JSON
```

## Исходные материалы

Для повторного выполнения экспериментов необходимы два файла:

- `LLM instruct (2).pdf` - исходный PDF из папки `Лабораторные работы/3` репозитория `AI_services`;
- `SimpleLangchainRag.ipynb` - исходный Jupyter Notebook, из которого извлекается базовый шаблон промпта.

При клонировании репозитория эти файлы необходимо получить отдельно и поместить в `lab3/sources/`. Файлы в этом каталоге исключены из Git. Если исходные файлы уже есть в `_reference/`, копирование необязательно: `rag.py` ищет их там автоматически.

Копирование из локальной `_reference/` (PowerShell, корень проекта):

```powershell
New-Item -ItemType Directory -Path lab3/sources -Force | Out-Null
Get-ChildItem _reference -Recurse -File -Filter 'LLM instruct (2).pdf' | Select-Object -First 1 | Copy-Item -Destination lab3/sources/
Get-ChildItem _reference -Recurse -File -Filter 'SimpleLangchainRag.ipynb' | Select-Object -First 1 | Copy-Item -Destination lab3/sources/
```

Для воспроизведения опубликованных результатов требуется та же версия PDF. SHA-256 использованного файла: `c1984bb50a5b90fddb895fdc3a0f72e5bc977148c9f63ef6040cbe7a3e1f0d98`. Проверка:

```powershell
(Get-FileHash 'lab3/sources/LLM instruct (2).pdf' -Algorithm SHA256).Hash
```

Исходный шаблон промпта считывается из `SimpleLangchainRag.ipynb`; его SHA-256 указан в `results/06_prompts.json`. Изменение содержания исходных материалов может привести к несовпадению количества фрагментов, оценок и сохранённых результатов.

## Среда и запуск

Windows, PowerShell из корня проекта:

```powershell
py -3.12 -m venv lab3/.venv
& '.\lab3\.venv\Scripts\python.exe' -m pip install -r lab3/requirements.txt
```

Требуется [Ollama для Windows](https://docs.ollama.com/windows) версии 0.11.10 или новее. Запуск в отдельном терминале, если сервер ещё не запущен:

```powershell
ollama serve
```

В другом терминале:

```powershell
ollama pull embeddinggemma
ollama pull llama3.2:1b
ollama list
Invoke-RestMethod http://127.0.0.1:11434/api/tags
```

Для портативной сборки путь к исполняемому файлу и каталог моделей задаются только для текущей сессии:

```powershell
$env:OLLAMA_MODELS = (Resolve-Path 'lab3/.ollama-runtime/models').Path
& '.\lab3\.ollama-runtime\ollama.exe' serve
```

Запуск JupyterLab:

```powershell
& '.\lab3\.venv\Scripts\python.exe' -m jupyterlab --notebook-dir lab3
```

В PyCharm интерпретатором выбирается `lab3/.venv/Scripts/python.exe`. При необходимости выполнить и сохранить все ячейки из PowerShell:

```powershell
& '.\lab3\.venv\Scripts\python.exe' lab3/run_notebook.py
```

## Методика

Базовое разбиение: 1000 символов, перекрытие 200, k=3. Модель генерации `llama3.2:1b`, эмбеддинги `embeddinggemma`. Температура 0, seed 42, окно генерации 8192, предел ответа 512 токенов. Версии библиотек, runtime и точные идентификаторы моделей фиксируются в [environment.json](results/environment.json).

- PDF загружается постранично; ссылки используют порядковую страницу PDF, начиная с 1. У титульной страницы нет напечатанного номера. `start_index` относится к извлечённому тексту страницы.
- В задании 2 предусмотрены две серии: перекрытие 10 из запроса и 100 из методички. В каждой серии независимо сравниваются размеры 500, 1000 и 2000. В остальных опытах сохранены базовые параметры, кроме исследуемого фактора.
- Hit Rate@3 = число вопросов с хотя бы одним достаточным фрагментом в top-3 / число вопросов. В автоматической проверке ищется целый заранее размеченный достаточный отрывок на соответствующей странице. Альтернативные достаточные отрывки можно отметить при смысловой проверке; совпадение пары терминов не считается доказательством.
- Почти одинаковые результаты: Жаккар не ниже 0.75 по множествам 5-грамм токенов. Метрика учитывает все пары в top-3.
- В задании 6 исходный промпт считывается без изменений из учебного ноутбука. Сравниваемые промпты получают один и тот же контекст. Отсутствие ответа проверено по полному PDF; сохранены термины для навигации по всему документу, страницы совпадений и смысловое обоснование.
- В памяти остаются три завершённых обмена на сессию. История используется для преобразования уточнения в поисковый запрос. Генерация опирается на извлечённый PDF, а не на историю.

## Разметка

В `*_details.json` записаны вопросы, фактические поисковые запросы, полные фрагменты с метаданными, ответы и отпечатки результатов. Поля `review_key` и `fingerprint` связывают разметку с конкретной выдачей и ответом. Отличающемуся результату старый балл не переносится.

Шкала: 0 - неверно, необоснованный отказ при наличии ответа или существенное неподтверждённое утверждение; 1 - частичный правильный ответ; 2 - полный подтверждённый ответ. Для вопросов без ответа отдельно размечаются `refusal` (отказ), `unsupported` (неподтверждённое утверждение) и `invalid` (вывод без ответа и без явного отказа). Корректность ID и страницы проверяется программно, подтверждение утверждения - сверкой с полным текстом конкретного процитированного фрагмента. Пропуск означает, что оценка не выполнена.

## Результаты

Извлечён текст со всех 68 страниц, базовое разбиение дало 246 фрагментов, размер эмбеддинга - 768. Созданы девять плотных индексов; BoW построен на тех же 246 фрагментах.

Ноутбук выполнен в двух независимых ядрах. Совпали ранжированные фрагменты и ответы по всем 141 строкам экспериментов, базовый запрос и сводные таблицы. Подробности в [reproducibility.json](results/reproducibility.json) и [validation.json](results/validation.json).

| Опыт | Результат |
|---|---|
| [1. Полнота](results/01_coverage_summary.csv) | Первые 5: 3/6, 50%; полный индекс: 1/6, 16.7%. Средний балл генерации 0 у обоих. |
| [2. Размер](results/02_size_summary.csv) | 1/10, 10% для всех размеров в обеих сериях. При перекрытии 10: 419, 217, 127 фрагментов; при 100: 476, 228, 128. |
| [3. Перекрытие](results/03_overlap_summary.csv) | 0/5 при 0, 100 и 200. При 200 похожие пары найдены в 3/5 выдач; при 0 и 100 таких пар нет. |
| [4. Метод поиска](results/04_search_summary.csv) | BoW: 4/5 на точных вопросах и 0/5 на перефразировках; плотный поиск: 1/5 и 0/5 соответственно. |
| [5. Источники](results/05_citations_summary.csv) | 5 ссылок нужного формата в 3 ответах. Все ID и страницы верны, 1 ссылка подтверждает ответ. |

| [7. Диалог](results/07_dialogue_summary.csv) | 3 сессии, 9 реплик, 6 уточнений. 2/6 корректных переформулировок; 0/6 успешных поисков с переписыванием и без него. Изоляция, окно 3, вытеснение и очистка подтверждены. |

Для Q01 при точном поиске BoW фрагмент на странице 42 упоминает демонстрационный набор SFT, но не подтверждает в одном фрагменте все элементы эталонного ответа (примеры желаемого поведения, составленные разметчиками). Поэтому этот поиск оценён как неуспешный. Исправление относится к разметке сохранённой выдачи, а не к повторной генерации или изменению поискового метода.

При перекрытии 100 и 200 все пять отрывков из задания 3 сохранились целиком, но не попали в top-3. В задании 2 размер 2000 увеличил объём контекста без прироста Hit Rate. Поэтому 1000 остаётся исходной настройкой, вывод об оптимуме не делается. У плотного поиска часто встречались короткие подписи к рисункам: на контрольной выборке [порядок DocArray совпал с прямым косинусом NumPy](results/ranking_check.json).

Субъективная составляющая ограничена явной смысловой разметкой. Для повторного измерения результаты проверяются по фактическим выходам новой модели и выдачи. Проверка сохранённого ноутбука:

```powershell
& '.\lab3\.venv\Scripts\python.exe' lab3/verify_results.py
```
